### `src/client/index.css` (config/CSS, transform)

**Analog:** the exact `@container mdfield (min-width: 480px)` block being overridden — current source, lines 63-85, verified by direct read:
```css
/* Markdown field (edit + preview) */
.markdown-field { container-type: inline-size; container-name: mdfield; }
.markdown-field-tabs { display: flex; border-bottom: 1px solid #332922; }
.markdown-field-body { display: flex; flex-direction: column; }
.markdown-field-textarea { ... }
.markdown-field-preview-pane { padding: 12px; }
.markdown-field-pane-hidden { display: none; }

@container mdfield (min-width: 480px) {
  .markdown-field-body { display: grid; grid-template-columns: 1fr 1fr; gap: 16px; align-items: stretch; }
  .markdown-field-tabs { display: none; }
  .markdown-field-pane-hidden { display: block; }
}
```

**Pattern to add** — three two-class compound-selector override rules, placed immediately after line 85 (after the `@container` block closes), each targeting one of the three properties the `@container` block flips:
```css
.markdown-field-force-tabs .markdown-field-tabs { display: flex; }
.markdown-field-force-tabs .markdown-field-body { display: flex; flex-direction: column; }
.markdown-field-force-tabs .markdown-field-pane-hidden { display: none; }
```

**Why this works unconditionally (no `!important`, no duplication):** every rule being overridden is a single-class selector (specificity 0,1,0) whether declared at base level or inside `@container` (at-rules gate applicability, not specificity). The new rules are two-class descendant selectors (specificity 0,2,0), which wins regardless of source order. Do not duplicate these rules inside the `@container` block and do not add `!important` — both would be dead/redundant code per this phase's Anti-Patterns.

## Shared Patterns

### `onChange` raw-string contract
**Source:** established across Phase 2 (`.planning/phases/02-markdown-editing-character-location-fields/`) and Phase 3 (`.planning/phases/03-markdown-editing-session-prep-fields/`), most directly `updateOverview` in this same `SessionLog.jsx`.
**Apply to:** `updateNotes` in `SessionLog.jsx` — change from `(e) => ...e.target.value` to `(v) => ...v`.
```jsx
onChange={v => updateNotes(v)}
```

### `UPDATE_SESSION` full-payload persistence
**Source:** unchanged since Phase 1 — `dispatch({ type: 'UPDATE_SESSION', payload: { ...session, <field>: <value> } })`, flushed to `PUT /api/sessions/{id}` via `dispatchWithPersist` in `src/client/context/AppContext.jsx`.
**Apply to:** `updateNotes`'s dispatch body — unchanged shape, only the value source changes.

### Component-level opt-in boolean prop convention
**Source:** `MarkdownField.jsx`'s existing `autoFocus = false` prop.
**Apply to:** the new `forceTabs = false` prop — same destructuring-with-default style, same "only appends behavior when explicitly passed `true`" contract, preserving backward compatibility for the 10 existing call sites.

### BEM-ish CSS modifier-class convention
**Source:** existing `.markdown-field-*` naming in `src/client/index.css` (`.markdown-field-tabs`, `.markdown-field-body`, `.markdown-field-pane-hidden`).
**Apply to:** the new `.markdown-field-force-tabs` modifier class — same `.markdown-field-*` prefix, composed as a descendant selector rather than a new base rule.
