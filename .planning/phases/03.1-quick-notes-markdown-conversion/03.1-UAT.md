## Tests

### 1. Live markdown preview in Quick Notes
expected: Type `# My heading` then `- an item` into Quick Notes (right column of Session tab), click Preview. Heading renders amber, bullet renders as a list item.
result: pass
notes: Tested live via Docker stack (rebuilt to pick up phase 3.1 + review-fix commits) using the Claude in Chrome extension. Typed `# My heading`, `- an item`, `**bold reminder**` — Preview rendered heading in amber H1, bullet list item, and bold text correctly.

### 2. Forced tabs at any width (Quick Notes never splits)
expected: At full ultrawide/maximized width, Quick Notes still shows Edit/Preview tabs (single pane); Overview & Hook (left column) switches to side-by-side split at the same width.
result: pass
notes: Verified via direct CSS/DOM inspection (more rigorous than visual-only, since resize_window didn't reliably reflect in screenshots this session) — at a genuinely wide container (619px, well past the 480px breakpoint), Quick Notes measured `bodyDisplay: flex`, `tabsVisible: true`, `hasForceClass: true`. Simultaneously, Overview & Hook at 750px measured `bodyDisplay: grid` (split-view). Confirms `forceTabs` correctly overrides the container-query split-view regardless of actual width.

### 3. Identical chrome to other MarkdownField instances
expected: Quick Notes uses default 14px sans-serif body font (monospace gone), toolbar (B/I/H/•) and "Markdown supported" hint match every other field.
result: pass
notes: Confirmed visually — sans-serif font (not monospace), toolbar buttons and "Markdown supported" hint identical in styling to Overview & Hook's instance.

### 4. DC-button auto-log regression
expected: Click a Toolkit ★ Save action, switch to Quick Notes — appended `[HH:MM] ...` line appears on its own line in both Edit and Preview panes.
result: pass
notes: Rolled a d20 in the Toolkit Dice Roller, clicked ★ Save. Quick Notes' raw value correctly appended `\n[13:45] Rolled 1d20 = 7`. Preview pane rendered it on its own separate line below "bold reminder", not merged — remark-breaks handles the new call site correctly.

### 5. Persistence across reload
expected: Type markdown into Quick Notes, reload — both raw markdown and rendered preview survive.
result: pass
notes: Initial attempt showed a truncated value after reload ("**b" instead of "**bold reminder**"); investigated via direct textarea/API inspection and confirmed this was a test-automation artifact (a click/select sequence that didn't land on the focused element after a prior tab-switch), not a real app bug — a clean retype with confirmed focus produced an exact-match value both before and after reload, cross-checked against `GET /api/sessions/{id}` directly.

### 6. WR-02 toolbar-disabled fix — cross-breakpoint re-enable (other 10 call sites)
expected: On a non-forceTabs MarkdownField (e.g. Overview & Hook), click Preview while narrow, then widen past 480px so it splits — toolbar buttons re-enable (not stuck disabled).
result: pass
notes: Since window resize wasn't reliably taking effect this session, forced a real layout change via inline style on the field's container (700px, confirmed via getBoundingClientRect and computed `display: grid`). Toolbar buttons were disabled immediately at narrow+Preview (correct), then re-enabled (`disabled: false`) after the ResizeObserver callback fired (~1s) once the container crossed 480px — confirming `useIsSplitView` correctly tracks actual pane visibility rather than stale `activeTab`.
