# Phase 3.1: Quick Notes Markdown Conversion - Context

**Gathered:** 2026-07-13
**Status:** Ready for planning
**Source:** Direct conversation (urgent insertion after Phase 3 UAT) — not a `/gsd-discuss-phase` session. The user gave explicit, unambiguous requirements in chat; this document restates them faithfully rather than re-deriving them through interactive questioning.

<domain>
## Phase Boundary

This phase wires the shared `MarkdownField` component into the Session Log tab's "Quick Notes" field (`session.sessionNotes`), the last remaining plain-`<textarea>` prose field discovered during Phase 3's UAT. Unlike every other `MarkdownField` call site (Phase 2's 6 sites + Phase 3's 4 sites), this one must **always** show the Edit/Preview tab toggle — never the side-by-side split view — regardless of container width, because it sits in the narrowest column of the Session tab's 3-column grid layout (`grid-cols-[1.2fr_1fr_1fr]`), where a split view would be too cramped to read.

It does not touch: the TipTap rich-text "Session Notes" heading/editor in the middle column (`session.sessionLog`, `RichTextEditor.jsx` — explicitly out of scope per PROJECT.md, unrelated field despite the confusing shared "Session Notes" label), Character/Location `sessionNotes` fields (already markdown since Phase 2), or any other Session Prep field (Phase 3, already shipped).

</domain>

<decisions>
## Implementation Decisions

### Field Scope
- **D-01:** Only `session.sessionNotes` ("Quick Notes", right column of the Session tab, `SessionLog.jsx` lines ~189-199) gets `MarkdownField`. Confirmed explicitly: the user only asked about this field, not the TipTap "Session Notes" editor above it in the middle column.

### Tab-vs-Split Behavior (the core decision of this phase)
- **D-02 (user-mandated, non-default):** Quick Notes' `MarkdownField` instance must **always** render the Edit/Preview tab toggle and single-pane view — it must never switch to the side-by-side split view that the container-query breakpoint (`@container mdfield (min-width: 480px)` in `src/client/index.css`) triggers for every other instance. This is an explicit override of the existing Phase 2 D-06 behavior (container-width-driven auto-switching), scoped to this one call site only.
- **D-03:** Everything else about this field's `MarkdownField` instance — toolbar (Bold/Italic/Heading/Bulleted-list), `MarkdownPreview` rendering, unbounded auto-grow, empty-state text, dark-theme chrome (border/background) — must be identical to every other instance. The only difference from the rest of the app is the forced-tabs behavior in D-02; nothing else about "the preview" (rendering, styling) should diverge.

### Component API
- **D-04 (Claude's technical judgment, confirmed reasonable by user's description of the ask):** `MarkdownField` needs a new opt-in prop (e.g. `forceTabs`) that adds a modifier class to the component's root `.markdown-field` div. The CSS override lives in `src/client/index.css`, adding rules that keep `.markdown-field-tabs` visible and `.markdown-field-body`/`.markdown-field-pane-hidden` in single-pane mode even inside the `@container mdfield (min-width: 480px)` block. This is the only clean way to force tab-mode for one instance without touching the shared component's behavior everywhere else. No other call site should pass this prop.

### Claude's Discretion
- Exact prop name (`forceTabs` or equivalent) and CSS modifier class name (e.g. `.markdown-field-force-tabs`) — pick names consistent with the existing `markdown-field-*` BEM-ish convention already in `index.css`.
- Whether the CSS override needs `!important` or can rely on source-order/specificity alone (duplicate the override rule both outside and inside the `@container` block) — verify empirically once implemented.
- Whether `MarkdownField`'s toolbar-disabled-on-preview-tab behavior (`toolbarDisabled = activeTab !== 'edit'`) needs any adjustment for the forced-tabs case — expected: no change needed, since tabs still exist and still drive `activeTab` the same way, just permanently instead of only below 480px.

</decisions>
