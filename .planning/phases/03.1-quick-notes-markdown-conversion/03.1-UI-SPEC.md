## Spacing Scale

Declared values (must be multiples of 4), unchanged from Phase 2/3 — this phase adds no new spacing tokens:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Toolbar button vertical padding (`py-1`) |
| sm | 8px | Toolbar button horizontal padding (`px-2`), gap between toolbar button groups |
| md | 16px | Split-view editor/preview column gap (`.markdown-field-body` grid) — **not visually reachable at this call site**, see Exceptions below; vertical spacing between Session tab right-column sections (`space-y-6` in `SessionLog.jsx` line 156) |
| lg | 24px | Not used by this phase |
| xl | 32px | Not used by this phase |
| 2xl | 48px | Not used by this phase |
| 3xl | 64px | Not used by this phase |

Exceptions:

- **This is the one `MarkdownField` instance in the entire app that never reaches the 480px container-query split-view breakpoint by design**, regardless of actual measured width. Every other instance (Phase 2's 6 sites, Phase 3's 4 sites) lets `@container mdfield (min-width: 480px)` drive the split view automatically. Quick Notes sits in the rightmost column of `grid-cols-[1.2fr_1fr_1fr]` (Session tab), the narrowest of the three columns, and per CONTEXT.md D-02 the tab-toggle/single-pane view must be forced permanently here — the split view must never appear at this site even if the column happens to measure wider than 480px on an ultrawide monitor.
- **No `max-height`/internal scroll on this field** (unchanged convention from Phase 2/3) — the containing column already scrolls (`lg:overflow-y-auto` on the right column, `SessionLog.jsx` line 156).
- **Container width is otherwise irrelevant to this phase's CSS** — the `forceTabs` override (see below) is unconditional, not a narrower breakpoint; it does not depend on measuring or tuning a new pixel value.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 400 | 1.4 |
| Body | 14px | 400 | 1.6 |
| Heading | 18px | 700 | 1.3 |
| Display | 22px | 700 | 1.2 |

Unchanged shared CSS (`.markdown-preview`/`.markdown-field-textarea` rules in `index.css` lines 49-84 — confirmed present, no edits needed):

- **Label (12px/400):** Edit/Preview tab labels, toolbar tooltips ("Bold", "Italic", "Heading", "Bulleted list"), "Markdown supported" hint caption, the existing "DC button clicks are logged here automatically." helper caption above the field (unchanged, plain text, not part of `MarkdownField`).
- **Body (14px/400, line-height 1.6):** Textarea input text and rendered preview paragraph/list/blockquote/inline-code text — identical size to every other `MarkdownField` instance.
- **Heading (18px/700)** and **Display (22px/700):** Markdown preview `h2`/`h3` and `h1` respectively, rendered in accent color `#d4a574` (existing `.markdown-preview` rule, unchanged) — will appear rarely in a Quick Notes field but must render identically to every other site if the DM types `#`/`##` syntax.

**Decision — drop the monospace override (resolves CONTEXT.md's open discretion item):** The current Quick Notes `<textarea>` uses `font-mono text-xs` (`inputCls + ' font-mono text-xs'`). This monospace/12px styling is **not carried over** to the new `MarkdownField` instance. Rationale: CONTEXT.md D-03 is explicit that "everything else about this field's `MarkdownField` instance ... must be identical to every other instance" — no other `MarkdownField` call site uses a monospace font or 12px body text, and inventing a one-off `textareaClassName` override here would itself be the kind of divergence D-03 rules out. `MarkdownField`'s default `textareaClassName=''` (14px sans-serif body text, matching Body role above) is used unmodified, same as every other site.

## Component-Specific Integration Contracts

These sections resolve CONTEXT.md's D-04 discretionary questions (prop name, CSS modifier name, `!important` vs. specificity) and are binding for the plan and executor, not open questions.

### Forced tab-toggle mode — `forceTabs` prop

**Prop name:** `forceTabs` (boolean, default `false`) — consistent with the existing camelCase prop convention on `MarkdownField` (`autoFocus`, `textareaClassName`).

**Usage:** Only `SessionLog.jsx`'s Quick Notes call site passes `forceTabs`. No other call site (10 existing sites across Phase 2/3) is touched or receives this prop — its default `false` value means zero behavior change everywhere else.

```jsx
<MarkdownField
  value={session.sessionNotes}
  onChange={v => updateNotes(v)}
  forceTabs
  placeholder="Quick notes, reminders, DC results..."
/>
```

**Root div wiring in `MarkdownField.jsx`:** add the modifier class conditionally alongside the existing `markdown-field` class:

```jsx
<div className={`markdown-field ${forceTabs ? 'markdown-field-force-tabs' : ''} border border-[#332922] rounded-lg bg-[#161310] ${className}`}>
```

**CSS modifier class:** `.markdown-field-force-tabs`, added to `src/client/index.css` immediately after the existing `@container mdfield (min-width: 480px)` block (lines 81-85):

```css
.markdown-field-force-tabs .markdown-field-tabs { display: flex; }
.markdown-field-force-tabs .markdown-field-body { display: flex; flex-direction: column; }
.markdown-field-force-tabs .markdown-field-pane-hidden { display: none; }
```

**Resolved: no `!important` needed.** Each override selector is a two-class compound selector (`.markdown-field-force-tabs .markdown-field-tabs`, etc.), which has higher CSS specificity (0,2,0) than the `@container` block's single-class selectors (0,1,0) it must beat (`.markdown-field-tabs`, `.markdown-field-body`, `.markdown-field-pane-hidden`, each 0,1,0). Higher specificity wins regardless of source order or container-query state, so these three rules do not need to be duplicated both outside and inside the `@container` block, and do not need `!important`. Place them anywhere in the stylesheet after the base `.markdown-field-*` rules (immediately after the `@container` block is the clearest location for future readers).

**Toolbar-disabled behavior:** No change needed to `toolbarDisabled = activeTab !== 'edit'` — tabs still exist and still drive `activeTab` identically when `forceTabs` is set, just permanently instead of only below 480px. Confirmed as expected-no-change per CONTEXT.md's discretion note; the executor does not need to touch this line.

### `SessionLog.jsx` call-site wiring

1. Replace the `<textarea>` at lines 192-198 with `<MarkdownField value={session.sessionNotes} onChange={v => updateNotes(v)} forceTabs placeholder="Quick notes, reminders, DC results..." />`.
2. Change `updateNotes(e)` (line 48) to `updateNotes(v)`, and its dispatch payload from `sessionNotes: e.target.value` to `sessionNotes: v` — matching the established raw-string `onChange` contract used by every other `MarkdownField` call site (e.g. Phase 3's `updateOverview`). This is a required signature change, not optional.
3. Do not add a `className`/`textareaClassName` override at this call site — per the Typography section above, the monospace/12px styling is intentionally dropped, and no other visual override applies.
4. The "Quick Notes" `<h2>` and the "DC button clicks are logged here automatically." caption stay exactly as they are today, outside and above `MarkdownField` — this phase does not touch them.
