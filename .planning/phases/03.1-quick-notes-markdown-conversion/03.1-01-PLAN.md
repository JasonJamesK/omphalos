<objective>
Wire the shared `MarkdownField` component into the Session Log tab's "Quick Notes" field (`session.sessionNotes`) — the last remaining plain-`<textarea>` prose field in the app — satisfying MDED-11. This one call site must **always** render the Edit/Preview tab toggle (single-pane), never the side-by-side split view every other `MarkdownField` instance uses, because it sits in the narrowest column of the Session tab's `grid-cols-[1.2fr_1fr_1fr]` layout (D-02).

Achieved by an additive `forceTabs` opt-in prop on `MarkdownField` (D-04) plus three CSS override rules, then swapping the Quick Notes `<textarea>` for `<MarkdownField forceTabs>` (D-01) with the monospace styling dropped so it is identical to every other instance except the forced tabs (D-03).

Purpose: Complete the app-wide markdown-field rollout (this is the 11th call site) so the DM formats Quick Notes the same way as every other long-text field, discovered as an unconverted field during Phase 3's UAT.
Output: One additive component prop, one CSS modifier class (3 rules), one call-site swap — no new files, no new packages, no backend change.
</objective>

## Phase Goal (MVP user story)

**As a** DM, **I want to** write the Session Log "Quick Notes" field in markdown with a live preview that always uses the Edit/Preview tab toggle, **so that** I can format my at-a-glance session notes the same way as every other field without a split view cramping the narrow right column.

> Derived faithfully from the ROADMAP Phase 03.1 `**Goal:**` line and its three success criteria — not invented. The entire phase is a single atomic vertical slice (one component prop, one CSS rule set, one call site); the user-facing capability lands in Task 2, enabled by the shared-component change in Task 1.
