<crop_site_wiring_contract>
Form image state = `hasImage` (bool, init from the loaded character's `hasImage`), `originalImageData` (base64|null, set only on a brand-new upload), `croppedImageData` (base64|null, set on new upload or re-crop).
1. File input onChange(file): `isGifFile(file)` -> skip crop: `originalImageData = await blobToBase64(file)`, `croppedImageData = null`, `hasImage = true`, show the inline GIF notice ("Animated GIFs are saved as-is — cropping isn't applied to GIFs.", `#999999`), after the existing 5MB size gate. Else -> open `<ImageCropModal file={file} aspectW={3} aspectH={4} title="Crop Portrait" onSave onClose />`.
2. New-upload onSave(originalFile, croppedBlob) -> `originalImageData = await blobToBase64(originalFile)`, `croppedImageData = await blobToBase64(croppedBlob)`, `hasImage = true`.
3. Re-crop -> `fetchImageBlob(sessionCharacterImageUrl(char, sessionId, 'original'))` (or the local `originalImageData` if unsaved) -> open ImageCropModal; onSave sets ONLY `croppedImageData` (leave `originalImageData` null so the stored original is preserved — IMG-02).
4. Remove -> `hasImage=false`, `originalImageData=null`, `croppedImageData=null`.
5. Preview `<img>`: local `croppedImageData` -> `data:image/jpeg;base64,${croppedImageData}`; else if `hasImage` (or linked) -> `sessionCharacterImageUrl(char, sessionId)`; else placeholder.
6. Because the character form spreads `...char` and the session upsert serializes the whole session, the new fields flow to the backend automatically once they are on the form/character object — no db/index.js change is needed.
</crop_site_wiring_contract>
