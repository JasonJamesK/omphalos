<crop_site_wiring_contract>
Shared pattern for every crop site in this phase (applies here to GlobalCharacterModal + GlobalLocationModal). Form image state becomes three fields: `hasImage` (bool), `originalImageData` (base64 string | null, set only on a brand-new upload), `croppedImageData` (base64 string | null, set on new upload or re-crop).

1. File input `onChange(file)`:
   - `isGifFile(file)` true -> skip crop: `originalImageData = await blobToBase64(file)`, `croppedImageData = null`, `hasImage = true`; show the inline GIF notice ("Animated GIFs are saved as-is — cropping isn't applied to GIFs.", `#999999`, in the file-error caption slot). Keep reusing the existing `MAX_IMAGE_MB` size gate (readImageFile or a direct `file.size` check) before accepting.
   - else -> open `<ImageCropModal file={file} aspectW aspectH title onSave onClose />`.
2. `ImageCropModal onSave(originalFile, croppedBlob)` for a NEW upload -> `originalImageData = await blobToBase64(originalFile)`, `croppedImageData = await blobToBase64(croppedBlob)`, `hasImage = true`; close modal.
3. "Re-crop" -> `fetchImageBlob(getImageUrl(kind, id, 'original'))` then open `<ImageCropModal file={blob} .../>`; its `onSave(_, croppedBlob)` sets ONLY `croppedImageData = await blobToBase64(croppedBlob)` (leave `originalImageData` null so the backend preserves the stored original — IMG-02). If the entity has no stored original yet (unsaved new form still holding a local `originalImageData`), re-crop from that local original instead.
4. "Remove" -> `hasImage = false`, `originalImageData = null`, `croppedImageData = null`.
5. Preview `<img>` in the form: if `croppedImageData` (local) -> `src={`data:image/jpeg;base64,${croppedImageData}`}`; else if `hasImage` -> `src={displayUrl}` (the endpoint URL); else render the existing placeholder.
6. Save payload: include `hasImage`, `originalImageData`, `croppedImageData` (omit the old `imageBase64`/`portraitBase64` and pan fields).
</crop_site_wiring_contract>
