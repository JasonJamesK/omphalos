<url_contract>
`getImageUrl(kind, id, variant, sessionId)` returns the binary-endpoint path (Plan 03 implements these exact routes — keep them in lockstep):
- kind `'session-character'`: `/api/sessions/{sessionId}/characters/{id}/portrait/{variant}`
- kind `'session-location'`: `/api/sessions/{sessionId}/locations/{id}/image/{variant}`
- kind `'global-character'`: `/api/characters/{id}/portrait/{variant}`
- kind `'global-location'`: `/api/locations/{id}/image/{variant}`
- `variant` is `'cropped'` (display; server falls back to original) or `'original'` (re-crop source).

**Session display resolvers (encode own-vs-linked-vs-none, so display sites stay dumb):**
- `sessionCharacterImageUrl(char, sessionId, variant='cropped')` = if `char.hasImage` -> `getImageUrl('session-character', char.id, variant, sessionId)`; else if `char.globalCharacterId` -> `getImageUrl('global-character', char.globalCharacterId, variant)`; else `null` (render placeholder). This is the mechanism by which an add-from-library character shows the library entry's image WITHOUT copying bytes across the API.
- `sessionLocationImageUrl(loc, sessionId, variant='cropped')` = if `loc.hasImage` -> session-location URL; else if `loc.globalLocationId` -> global-location URL; else `null`.
- `fetchImageBlob(url)` = `fetch(url, { credentials: 'include' }).then(r => r.ok ? r.blob() : null)` — used by the re-crop flow to pull the stored `/original` as a Blob to feed back into ImageCropModal.
</url_contract>
