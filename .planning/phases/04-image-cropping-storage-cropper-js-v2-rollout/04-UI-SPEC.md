# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled React components, no headless UI library (Radix/Base UI) in use anywhere in the codebase. This phase adds exactly one new visual-surface dependency: `cropperjs` v2 (native Web Components — `<cropper-canvas>`, `<cropper-image>`, `<cropper-shade>`, `<cropper-handle>`, `<cropper-selection>`, `<cropper-grid>`, `<cropper-crosshair>`). This is a functional cropping engine, not a design system or component kit — it must be themed to match the existing dark palette (see Color section), not adopted with its own default styling. |
| Icon library | none — the app uses plain text/glyph buttons and text links, not an icon library (confirmed: `×` close glyph on every modal, `Re-crop`/`Remove` text links on every image-upload site, `⚠️` emoji glyph on `SaveFailureToast.jsx`). The new `ImageCropModal` MUST follow this exact convention — no icon-font/SVG-icon dependency introduced for crop-modal chrome (close button, zoom affordance, etc.). |
| Font | System stack: `-apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif` (declared on `body` in `src/client/index.css`; no custom webfont anywhere in the project) |

**shadcn gate note:** No `components.json` exists. This project has a mature, fully hand-rolled Tailwind + inline-hex-arbitrary-value dark theme (confirmed via direct read of `CropModal.jsx`, `SaveFailureToast.jsx`, `AddLocationModal.jsx` — all use literal `bg-[#211b17]`/`text-[#d4a574]`-style arbitrary Tailwind values, not `tailwind.config.js`'s stale named `bg1`/`bg2`/`bg3` tokens, which are unused by any component). Phases 2 and 3 already established the precedent of `Tool: none` for this exact reason. Introducing shadcn now would contradict the project's established convention and add an unrelated dependency mid-rollout of a different library (Cropper.js v2). **Decision: `Tool: none`, proceed without shadcn.** Registry safety gate: not applicable.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between "Re-crop"/"Remove" text-link pair; corner-handle visual size offset |
| sm | 8px | Gap between image preview and its action-link row; gap between modal heading and instruction caption |
| md | 16px | Modal card internal spacing between crop stage and action-button row (`mt-4` on the Cancel/"Crop & Save" row, matching current `CropModal.jsx`) |
| lg | 24px | Not used by this phase's new UI (reserved for section-level padding already established elsewhere) |
| xl | 32px | Not used by this phase's new UI |
| 2xl | 48px | Not used by this phase's new UI |
| 3xl | 64px | Not used by this phase's new UI |

Exceptions:
- **Modal card padding: 20px (`p-5`), not a strict 8-pt value.** This is an intentional carry-forward of `CropModal.jsx`'s existing `rounded-lg p-5` — CROP-05 requires the replacement to match existing modal chrome exactly, so this one non-8pt value is preserved rather than "corrected" to 16px/24px.
- **Cropper stage (`<cropper-canvas>`) fixed height: 400px, width: 100% up to `max-width: 600px`.** Replaces `CropModal.jsx`'s current `MAX_W=600 / MAX_H=500` display-size computation. A single fixed-height stage (matching the quest-board reference's `<cropper-canvas style="width:100%;height:400px;">`) works uniformly across this phase's two aspect ratios (3:4 portrait, 4:3 location) because Cropper.js v2's `CropperImage.$center('contain')` auto-fits the source image inside the canvas regardless of its native aspect ratio — unlike the old hand-rolled `CropModal`, the stage size no longer needs to be derived from the image's natural dimensions.
- **Corner/edge resize handles: visually ~10px (matching `CropModal.jsx`'s existing handle size) but MUST have a minimum 44px touch-hit-target on touch devices.** Cropper.js v2's `<cropper-handle>` elements are Web Components with their own internal hit-box sizing — verify during implementation that the default hit area meets 44px on touch; if not, apply `touch-action` / padding overrides. This is an accessibility exception to the 8pt visual scale, not a violation of it (visual size and hit-target size are declared separately, matching WCAG 2.5.5 target-size guidance).
- **No `max-height`/internal scroll on the crop modal card itself** — the crop stage has one fixed height (400px, above); the modal card sizes to its content (heading + caption + stage + button row) with no nested scroll region, matching `CropModal.jsx`'s current non-scrolling layout.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 400 | 1.4 |
| Body | 14px | 400 | 1.5 |
| Heading | 16px | 700 | 1.2 |
| Display | — | — | Not used by this phase — the crop modal has one heading tier only, no display-scale text |

**Role mapping (specific to this phase's `ImageCropModal` and upload-site UI):**
- **Label (12px/400):** Instruction caption under the modal heading (e.g. "Drag to reposition, scroll or pinch to zoom — {W}:{H} area"), the crop-modal's own size-ratio corner label (`{aspectW}:{aspectH}`, matches `CropModal.jsx`'s existing `fontSize:10` label bumped to the declared 12px Label token for scale compliance), file-size/type error text under the upload control, "Re-crop"/"Remove" text-link labels. Matches the existing `text-xs` convention (`Tailwind text-xs` = 12px) used throughout `AddLocationModal.jsx`/`CharacterModal.jsx`/`Library.jsx`.
- **Body (14px/400):** Not used inside the crop modal itself (which is caption/heading/button only) — reserved for any surrounding upload-flow copy this phase touches (none currently planned beyond existing Label-scale strings).
- **Heading (16px/700):** The crop modal's `<h3>` title ("Crop Portrait" / "Crop Location Image" — per-site, matches `CropModal.jsx`'s existing `title` prop convention with no explicit Tailwind size class, i.e. browser default 1rem/16px + `font-bold`). Color: accent `#d4a574` (unchanged from current behavior).
- All typography in this phase is a direct carry-forward of `CropModal.jsx`'s existing conventions — this phase does not introduce any new type scale, only re-declares the existing one in explicit px terms for contract precision (the component being replaced used unlabeled Tailwind defaults; the replacement must hit these exact values, not "whatever `text-xs`/unstyled `<h3>` currently render as" if Tailwind's defaults ever drift).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#161310` | Crop-modal overlay backdrop is `black/85` (not this token directly — see note below); this token is the "Crop & Save" button's text color and the general page background convention this phase's UI sits within |
| Secondary (30%) | `#211b17` | Crop-modal card background (CROP-05's explicit requirement: "`bg-[#211b17]` card") |
| Accent (10%) | `#d4a574` | See "Accent reserved for" below |
| Destructive | `#b24545` | Destructive/error text only — see "Destructive usage" below |

**Overlay note:** The crop modal's backdrop is `bg-black/85` (matches `CropModal.jsx`'s current exact value), not the `black/70` used by `SettingsModal.jsx`. CROP-05 requires matching `CropModal.jsx`'s own established chrome, not `SettingsModal.jsx`'s — this is a deliberate, existing divergence in the codebase (image-crop modals are darker-backdrop than settings/admin modals) and this phase preserves it rather than unifying it.

Accent reserved for:
- Crop-modal heading text color (`<h3>`, unchanged from current `CropModal.jsx`)
- "Crop & Save" primary button background (`bg-[#d4a574] text-[#161310]`, hover `#c49464`)
- "Re-crop" text-link color (existing convention across all 3 upload sites: `text-[#d4a574] hover:underline`)
- Cropper.js v2 selection theming: the `<cropper-selection>` border/outline and its move `<cropper-handle>`'s `theme-color` attribute MUST be set to `#d4a574` (do not ship Cropper.js v2's own default blue/quest-board's `rgba(255,193,7,0.35)` amber-yellow — both are off-brand; retheme to this project's exact accent hex)
- Rule-of-thirds grid lines inside the crop selection (`<cropper-grid>`), at ~35% opacity — matches `CropModal.jsx`'s existing `rgba(212,165,116,0.35)` grid-line treatment (212,165,116 = `#d4a574` in RGB)
- Corner/edge resize-handle fill color (`<cropper-handle>` elements at `action="n-resize"`/`"nw-resize"`/etc.), matching `CropModal.jsx`'s existing solid `#d4a574` handle fill
- Upload-empty-state dashed border + text on hover only (`hover:border-[#d4a574] hover:text-[#d4a574]`, matching existing `AddLocationModal.jsx`/`CharacterModal.jsx`/`Library.jsx` "Click to upload..." button)

No other element in this phase's scope may use the accent color. The Cancel button, modal card border/chrome, close (`×`) glyph, and all body/caption text use dominant/secondary/neutral tokens (`#332922` button background, `#40332a` hover, `#f0f0f0` primary text, `#999999` muted text/close-glyph default state), not accent.

**Destructive usage (`#b24545`):**
- "Remove" text-link color (existing convention, unchanged: `text-[#b24545] hover:underline`)
- File-size/type/read-error text under the upload control (existing convention, unchanged: `text-[#b24545]`)
- No new destructive *action* is introduced by this phase (removing a not-yet-saved local image selection is not a persisted-data delete — see Copywriting Contract's "Destructive confirmation" row). The `SaveFailureToast.jsx` red-accent-border convention (`border-l-[#b24545]`) is unaffected and out of scope.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **"Crop & Save"** — unchanged, CROP-05 explicit requirement. Applies at all 3 usage sites (Character Library, in-session Character portrait, Location image). |
| Modal heading | Per-site, matching current `title` prop convention: **"Crop Portrait"** (Character Library + in-session Character sites), **"Crop Location Image"** (Location site). Do not introduce a single generic "Crop Image" title — the per-site specificity already exists and CROP-04/05 require matching current behavior. |
| Modal instruction caption | **"Drag to reposition, scroll or pinch to zoom — select your {W}:{H} area."** Extends `CropModal.jsx`'s current caption ("Drag the highlighted box to select your {W}:{H} area") with the new CROP-08 zoom capability so users discover mouse-wheel/pinch-zoom without hunting for a hidden gesture. `{W}:{H}` are the per-site aspect ratio numbers (e.g. "3:4", "4:3"), unchanged interpolation. |
| Cancel | "Cancel" — unchanged. |
| Empty state (Character sites) | **"Click to upload portrait"** — unchanged, existing exact string (`CharacterModal.jsx`, `Library.jsx`). |
| Empty state (Location site) | **"Click to upload image"** — unchanged, existing exact string (`AddLocationModal.jsx`). |
| Populated-state actions | **"Re-crop"** / **"Remove"** — unchanged, existing exact strings at all 3 sites. "Re-crop" re-opens `ImageCropModal` against the retained original (IMG-02) rather than re-triggering the file picker — this is a *behavior* change this phase must implement (today "Re-crop" just re-opens the file picker via `fileRef.current?.click()`, forcing a full re-upload); the copy itself does not need to change to communicate this, since "Re-crop" already reads correctly for either behavior. |
| Animated-GIF notice (new, discretionary — recommended, not locked by 04-CONTEXT.md) | **"Animated GIFs are saved as-is — cropping isn't applied to GIFs."** Small `Label`-scale (`#999999`) caption shown inline near the upload control the first time a GIF is selected (D-04 causes the crop modal to silently never open for GIFs; without this line, a DM who selects a GIF and sees no crop modal appear may reasonably think the upload failed). Placement: same caption slot the file-size/type error currently occupies (`text-xs mt-1`), styled as informational (`#999999`) rather than destructive (`#b24545`) since it is not an error. Omit this if the planner/executor determines a toast is a better fit than inline caption — the *content* of the message is the contract, the exact delivery mechanism is left to implementation as long as it is not silent. |
| File-size error | **"Image is {X} MB — max allowed size is 5 MB."** — unchanged, existing exact string from `src/client/utils/imageUpload.js`'s `readImageFile`. Reused as-is; this phase does not change the size-gate copy. |
| Unreadable-file error | **"Could not read that file."** — unchanged, existing exact string from `readImageFile`. |
| Destructive confirmation | **N/A — no confirmation dialog.** "Remove" clears the locally-selected/edited image from in-memory form state only; it does not delete a persisted `OriginalImageData`/`CroppedImageData` row until the surrounding form's own Save/Create action is clicked (matches existing pre-save-non-destructive behavior at all 3 sites today). This phase introduces no new "delete an already-saved image" affordance requiring its own confirmation — IMG-02's re-crop flow reads the retained original, it does not add a standalone delete-original control. |
