<objective>
Fix PERSIST-02/D-01 at its source: the four frontend call sites that dispatch a partial `{ id, <field> }` `UPDATE_SESSION` payload. Because the backend `UpsertAsync` (unchanged by this plan) overwrites the whole session from whatever payload it receives, a partial dispatch blanks out every field the payload omits (Title, Characters, Locations, Encounters, PrepData, etc.). The fix makes each site send the full current session with only the changed field overridden — matching the safe full-payload convention already used elsewhere in the app.

Purpose: This is the highest-visibility data-loss bug — a DM editing the session log or renaming a session can silently lose all characters/locations on the next save. Per D-01, the fix stays entirely on the frontend; the backend contract (expects a full session payload) is unchanged.

Scope note: Debouncing per-keystroke saves is explicitly OUT OF SCOPE (D-06) — do not add debounce/throttle here. The pre-existing rapid-multi-field stale-closure edge case (RESEARCH.md Pitfall 3) is also out of scope; spreading the full session is strictly safer than today's wipe regardless.

Output: SessionPrep.jsx, TopBar.jsx, SessionLog.jsx (3 functions), and Toolkit.jsx all dispatch full-session `UPDATE_SESSION` payloads.
</objective>
