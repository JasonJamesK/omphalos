Output: `existing.PrepData` assigned in `UpsertAsync`; a `SessionCollectionSync.Diff` pure helper + per-entity field-copy glue replacing `RemoveRange`+reassign; green unit tests (`SyncCollection`) and integration tests (`PrepDataPersistsOnUpdate`, `CollectionDiffMerge`).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → API → repository | An authenticated DM's full-session PUT payload reaches `UpsertAsync`; child-entity Ids in that payload are client-controlled |
| repository → Postgres | Diff-merge issues add/update/remove against child rows; incorrect scoping could touch rows outside the caller's session |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering / Elevation of Privilege | Diff-merge child reconciliation in `UpsertAsync` (cross-user child-entity Id reuse) | high | mitigate | Diff-merge operates only on `existing.Characters/Locations/Encounters` loaded via the `s.Id == session.Id && s.UserId == session.UserId` query; no global lookup by child Id is added. A client-supplied child Id that does not belong to this session's loaded children is treated as an insert (scoped to this session), never as an update of another user's row. The `CollectionDiffMerge` integration test asserts add/update/remove stay within the seeded session. |
| T-01-02 | Denial of Service | Null/empty incoming child collections | low | accept | `SessionService.MapToEntity` already coalesces null child lists to empty (`r.Characters ?? []`) upstream of the repository (RESEARCH.md V5 row); `Diff` handles empty lists (unit-tested), so no crash path is introduced. |
</threat_model>
