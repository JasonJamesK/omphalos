# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** This phase is ~95% backend (session-persistence bug fixes; see `01-CONTEXT.md`). The only UI surface is **PERSIST-04**: a save-failure indicator shown when a session save request fails (currently silently swallowed via `.catch(() => {})` in `AppContext.jsx`). This UI-SPEC covers that single new component — `SaveFailureToast.jsx` — and nothing else. No other UI surface should be added under this phase.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled JSX + Tailwind utility classes (project-wide convention; see below) |
| Icon library | none — project uses plain emoji glyphs for icon-like elements (precedent: `⚠️` in `src/client/components/tabs/Toolkit.jsx:363`) |
| Font | system stack: `-apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif` (`src/client/index.css:11`, project-wide, not phase-specific) |

**Why "none" and not shadcn:** `components.json` is absent, and none of this codebase's ~15 existing modal/overlay components (`SettingsModal.jsx`, `DeleteConfirm.jsx`, `CropModal.jsx`, `AdminModal.jsx`, etc.) use a component library — all are hand-rolled Tailwind with arbitrary-value hex classes. `01-CONTEXT.md`'s "Claude's Discretion" section explicitly delegates "exact toast/banner component styling" with the instruction to match "the existing dark theme per `CLAUDE.md`." Introducing shadcn for one small component would break that consistency and is disproportionate to a single-component, mostly-backend phase. (This gate could not be posed as a live Y/n prompt in this non-interactive research pass — resolved via the discretion grant above rather than skipped silently.)

**⚠ Token discrepancy flag for executor:** `tailwind.config.js` defines named color tokens (`bg1: #1a1a1a`, `bg2: #2d2d2d`, `bg3: #3d3d3d`) that **do not match** `CLAUDE.md`'s documented palette or actual usage anywhere in `src/client/components`. Every existing component (`SettingsModal.jsx`, `DeleteConfirm.jsx`, etc.) uses **arbitrary-value Tailwind classes with the `CLAUDE.md` hex codes directly** (e.g. `bg-[#211b17]`, not `bg-bg2`). Build `SaveFailureToast.jsx` using the same arbitrary-value pattern with the hex codes in the Color section below — do NOT use the named `bg1`/`bg2`/`bg3`/`amber` tokens from `tailwind.config.js`, they resolve to the wrong colors.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between icon glyph and heading text |
| sm | 8px | Gap between heading and body line; internal button padding (vertical) |
| md | 16px | Toast card padding; offset from viewport edges; internal button padding (horizontal) |
| lg | 24px | (project-wide reference only — not used at this component's size) |

Exceptions: none — component fits entirely within the 4/8/16 scale already used by `SettingsModal.jsx` (`p-6`... note: `SettingsModal` itself uses `p-6`/24px for its larger modal card; this toast is intentionally smaller, so it uses `p-4`/16px card padding, still on-scale).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#161310` (`bg1`) | App page background — reference only, not directly used by the toast card itself |
| Secondary (30%) | `#211b17` (`bg2`) | Toast card background — matches every existing modal/panel (`SettingsModal`, `DeleteConfirm`, `CropModal`) |
| Accent (10%) | `#d4a574` (amber) | Reserved for: nothing in this component. This is an **error-state** component — amber (primary accent) is intentionally NOT used for its framing, to avoid diluting amber's meaning elsewhere in the app. If a future non-error toast variant is added, amber would apply only to that variant's action link — out of scope here. |
| Destructive / semantic (this component's primary color) | `#b24545` (red), hover/darker `#922b2b` | Left border stripe (4px, `border-l-4 border-l-[#b24545]`) on the toast card; the "Save failed" heading text color; the `⚠️` glyph — signals the error state, matching `DeleteConfirm.jsx`'s existing red-border-on-dark-card pattern for danger-flavored surfaces |
| Text primary | `#f0f0f0` (`text1`) | Not used as heading color here (heading uses red per above) — reserved for the dismiss `×` glyph's hover state |
| Text secondary | `#999999` (`text2`) | Body/detail message text; dismiss `×` glyph default (unhovered) state |

Accent reserved for: **nothing in this component** — explicitly not used, since this is a single-purpose error indicator and amber would blur the error signal with the app's primary-accent meaning (headings, active states, primary CTAs elsewhere).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Not applicable — this is a passive, dismissible indicator, not an action surface. No "Retry" button: the app's existing autosave-on-every-edit pattern (`dispatchWithPersist` → `saveSession`) already re-attempts the save on the DM's next edit, so a manual retry control would duplicate that behavior without being decided in `01-CONTEXT.md`. Adding one is out of scope for this UI-SPEC (see scope note at top). |
| Empty state | Not applicable — this component has no list/collection to be empty; it either renders (a failure occurred) or doesn't. |
| Error state (the component's only state) | Heading: **"Save failed"** — Body: **"Your last change wasn't saved. Edit again to retry, or check your connection."** |
| Destructive confirmation | Not applicable — dismissing the toast is non-destructive. It does not discard the DM's unsaved edit; that edit remains in local React state and will be re-sent on the next save trigger. No confirmation step needed for dismiss. |
| Dismiss control | `×` — same glyph, size (`text-2xl leading-none`), and hover behavior (`text-[#999999] hover:text-[#f0f0f0]`) as every existing modal close button (`SettingsModal.jsx:23`) |

## Interaction & Placement Contract

(Non-template addition — necessary because this component's entire purpose is *when/where/how it appears*, not just its visual styling.)

| Property | Value |
|----------|-------|
| Component file | `src/client/components/SaveFailureToast.jsx` (PascalCase, matches `DeleteConfirm.jsx`/`SettingsModal.jsx` naming convention) |
| Position | Fixed, bottom-right corner: `fixed bottom-6 right-6` (24px from both edges) |
| Width | `max-w-sm` (384px) — a compact corner toast, not a full modal-width card. Narrower than `DeleteConfirm.jsx`'s `w-96` (384px is close but intentionally capped via `max-w-sm` so it never grows to modal width) |
| Card shape | `bg-[#211b17] border-l-4 border-l-[#b24545] rounded-lg shadow-2xl p-4` |
| Z-index | `z-[100]` — must render above every existing overlay, since a save failure can occur while a modal is open (e.g. editing inside `CharacterModal`). Existing overlay stack tops out at `CropModal`'s `z-[80]`; `z-[100]` guarantees the toast is never hidden behind an open modal. |
| Entrance animation | Reuse the existing `.fade-in` class already defined in `src/client/index.css:64-68` (`opacity 0→1`, `translateY(-4px)→0`, `0.15s ease-out`) — do not add a new keyframe for a single small component |
| Auto-dismiss | None. The toast persists until the DM manually dismisses it via `×`. A silently auto-expiring failure toast would defeat the purpose of PERSIST-04 (the DM must not miss it). |
| Multiple failures | If a second save fails while a toast is already visible, update/replace the existing toast's content rather than stacking a second one — this codebase has no toast-stacking precedent and one is not needed for a single-session-save failure signal. |
| Dismiss interaction | Click `×` only. No click-outside-to-dismiss (unlike this codebase's modals, which use `bg-black/70` click-outside — a toast is non-blocking and has no backdrop, so click-outside doesn't apply). |
