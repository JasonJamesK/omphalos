## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Session-load race → data wipe | `GET /api/sessions` returns summary-only DTOs (no characters/locations/encounters/prepData/sessionLog). Every edit surface (TopBar title, SessionLog, SessionPrep, Toolkit) spreads `activeSession` into `UPDATE_SESSION` unconditionally. If the edit fires before the lazy full-detail fetch (`AppContext.jsx:243-250`) resolves, the outgoing payload is missing those fields; the backend treats missing as null/empty; the Phase 1 diff-merge fix then deletes every existing child row. Reproduces on ordinary use: switch sessions, type in the title fast. | blocking | Gate `dispatchWithPersist` on a `detailLoadedIds` set — refuse session-shaped persists until the full record has loaded. Exact patch in `01-REVIEW.md` CR-01. |
| Worktree self-reported `expected_base` can be wrong | Plan 01-03's executor returned `expected_base` as its own final commit SHA instead of the actual fork-base SHA it was given, which blocked `worktree.cleanup-wave`. | advisory | Before trusting a worktree agent's self-reported `expected_base`, cross-check with `git merge-base <target-branch> <worktree-branch>` if cleanup reports `base_mismatch`. Don't blindly re-trust the agent's own report. |
