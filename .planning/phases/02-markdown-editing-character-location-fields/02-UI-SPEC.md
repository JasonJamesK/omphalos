## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled React components, no headless UI library (Radix/Base UI) in use anywhere in the codebase |

Introducing shadcn now would contradict the project's established, deliberate conventions and this phase's own research. **Decision: `Tool: none`, proceed without shadcn.** Registry safety gate: not applicable.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Toolbar button vertical padding (`py-1`), icon-gap-equivalent spacing |
| sm | 8px | Toolbar button horizontal padding (`px-2`), gap between toolbar button groups, preview list-item vertical margin |
| md | 16px | Split-view editor/preview column gap, default field vertical spacing (`space-y-4`/`space-y-3` sites this ships in) |
| lg | 24px | Not used by new markdown UI in this phase (reserved for section-level padding already established elsewhere) |
| xl | 32px | Not used by new markdown UI in this phase |
| 2xl | 48px | Not used by new markdown UI in this phase |
| 3xl | 64px | Not used by new markdown UI in this phase |

Exceptions:
- **Container-query breakpoint: 480px.** This is a component-level layout threshold (native CSS `@container` rule switching `MarkdownField` between tab-toggle and side-by-side mode), not a spacing token. Per `02-RESEARCH.md` Pattern 2, it sits between the measured ~330px character-field container width (`CharacterModal.jsx`/`Library.jsx` two-column prose fields) and the ~520–640px location/`SessionNotes` single-column container width. Tune only if visual QA shows it landing wrong for a specific site — it is a CSS value, not a structural decision.
- **Split-view gap set to `md` (16px), not the 12px shown in `02-RESEARCH.md`'s example CSS snippet.** Overridden here for scale compliance — 16px is the nearest declared token and reads cleanly at both the ~330px and ~520–640px measured widths.
- **No `max-height`/internal scroll anywhere on the field** (editor or preview pane) — required by D-10; the containing modal already scrolls (`overflow-y-auto` at the modal's outer `<div>`, confirmed present at every usage site).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 400 | 1.4 |
| Body | 14px | 400 | 1.6 |
| Heading | 18px | 700 | 1.3 |
| Display | 22px | 700 | 1.2 |

**Role mapping (specific to this phase's markdown UI):**
- **Label (12px/400):** Edit/Preview tab-toggle labels, toolbar button tooltips (`title` attributes: "Bold", "Italic", "Heading", "Bulleted list"), the optional D-09 "Markdown supported" hint caption, empty-state copy in read-only "Shared Info" boxes. Matches the existing `lbl` convention (`text-xs text-[#999999]`) used across `CharacterModal.jsx`/`Library.jsx` forms.
- **Body (14px/400, line-height 1.6):** The `<textarea>`'s own input text AND the rendered markdown preview's paragraph/list/blockquote/inline-code text. Both panes MUST share this exact size/line-height so the split view (D-11) reads as one continuous typographic block, not two mismatched columns. 14px matches the existing `inp` class (`text-sm`) used by every textarea this component replaces; 1.6 line-height matches the existing `.tiptap-editor .ProseMirror` convention already in `index.css`.
- **Heading (18px/700):** Markdown preview `h2` **and** `h3` (both render at this size in this compact, single-field context — DM prose rarely needs three visually distinct heading tiers inside one bio/description field; hierarchy is carried by content order, not size).
- **Display (22px/700):** Markdown preview `h1` only — the largest heading a DM's markdown can produce inside a field.
- All markdown preview headings (h1/h2/h3) use accent color `#d4a574` per the Color contract below (matches `.tiptap-editor .ProseMirror h1/h2/h3` convention already in `index.css`).
- These are **fixed px values**, not the `em`-relative sizing shown in `02-RESEARCH.md`'s example CSS block — override that snippet with the exact px values above when writing `index.css`'s `.markdown-preview` rules, for contract precision.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#161310` | Page/panel background; `<textarea>` background (matches existing `inp` class `bg-[#161310]`) |
| Secondary (30%) | `#211b17` | Toolbar bar background, Edit/Preview tab-strip background (matches `RichTextEditor.jsx`'s toolbar `bg-[#211b17]`) |
| Accent (10%) | `#d4a574` | See "Accent reserved for" below |
| Destructive | `#b24545` | Not used by this phase — no destructive action is introduced. Token listed for completeness/consistency only; do not invent a new destructive control here. |

Accent reserved for:
- Markdown preview heading text color (`h1`, `h2`, `h3` — inline in rendered content, matches `.tiptap-editor .ProseMirror` heading color)
- Active/toggled toolbar button background + text color (mirrors `RichTextEditor.jsx`'s `btnCls(active)` pattern: `bg-[#d4a574] text-[#161310]` when active, `bg-[#332922] text-[#f0f0f0] hover:bg-[#40332a]` otherwise)
- Active tab indicator in the Edit/Preview toggle (narrow/tab-toggle mode)
- `<textarea>` focus border (matches existing `inp` class `focus:border-[#d4a574]`)

No other element in this phase's scope may use the accent color. Toolbar's inactive-state buttons, borders, container chrome, and preview body text all use the dominant/secondary/neutral text tokens (`#332922` borders, `#f0f0f0` primary text, `#999999` muted text), not accent.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | N/A — this phase introduces no new primary action button. Every usage site's existing Save/Cancel CTAs (per site, e.g. "Save", "Add Character", "Create Location") are unchanged. This phase's only new interactive labels are utility controls, listed below. |
| Tab toggle labels | "Edit" / "Preview" (narrow/tab-toggle mode only; side-by-side mode has no tabs, per `02-RESEARCH.md` Pattern 2) |
| Toolbar button tooltips | "Bold", "Italic", "Heading", "Bulleted list" — mirrors `RichTextEditor.jsx`'s `title` attribute convention (e.g. `title="Bold (Ctrl+B)"`); this toolbar does not wire real keyboard shortcuts, so omit the `(Ctrl+…)` suffix and use the plain action name only |
| Optional syntax hint (D-09, discretionary) | "Markdown supported" — small muted caption (Label style, `#999999`), placed inline in the existing toolbar row (right-aligned) so it adds zero new layout rows. Omit entirely at any usage site where it would wrap/crowd the toolbar at the ~330px character-field width. |
| Empty state heading | N/A — no heading; this is an inline empty-state row inside an existing read-only "Shared Info" box, not a standalone empty-state screen |
| Empty state body | "Nothing written yet." — shown in the D-05 read-only "Shared Info" preview when the underlying field value is empty (replacing `MarkdownPreview`'s current `return null` for blank values, so the linked-entity box never silently shows nothing with no explanation). For fields editable only in the Library (not in-session), append "Edit in the Library to add it." |
| Error state | N/A — this phase introduces no new error states. `react-markdown` degrades malformed markdown to plain text by design (no parse-failure UI needed); no new validation is added to the underlying plain-string fields. |
| Destructive confirmation | N/A — this phase introduces no destructive actions. Toolbar buttons only insert/wrap text (non-destructive, and preserve native Ctrl+Z per `02-RESEARCH.md` Pattern 4); no delete/remove control is added anywhere in this phase's scope. |
