<objective>
Wire the already-shipped `MarkdownField` component (built and UAT-hardened in Phase 2) into the four remaining Session Prep prose surfaces — the top-level Overview & Hook field, and the Notes, Callout, and Loot-item-description fields inside session-prep blocks — completing MDED-09's "one shared markdown component across all 4 field locations." This is pure integration: replace four `<textarea>` call sites with `<MarkdownField>`, resolve the two styling-integration decisions the UI-SPEC already locked (D-04 full chrome, D-05 Callout Option A), and land the required Loot list-key correctness fix that must accompany nesting a stateful component in a repeatable list.

Purpose: The DM currently writes character/location fields in markdown (Phase 2) but is still stuck with plain textareas for the highest-value prep prose (the session overview, read-aloud callouts, DM notes, loot descriptions). This phase closes that gap and makes all four field types consistent, satisfying MDED-01, MDED-02, and MDED-09. Phase 1 already fixed the `PrepData` persistence path these fields sit on, so markdown content will reliably persist on reload with no new backend work.

Output: Four edited frontend component files, no new files, no new dependencies, no backend/DB/migration changes.
</objective>
